# Stall Flush Logic
## Signals
### `DM_stall`
There is read or write operation to DMEM, and not yet received `dm_valid`. It will stall EX/M, ID/EX and IF/ID pipeline registers. 
The instruction in M stage will only launch one time, thus we need to check if `DM_stall` is setup on input for M/WB pipeline register.

### `M_Forward_Result_Ready`
If the result in M stage for forwarding is ready or not. Two condition:
1. Not a read operation.
2. A read operation but recived `dm_valid`.

### `EX_Forward_Stall`
Generated by forwarding module, meaning that CPU needs to stall for forwarding.

### `FW_dep_stall`
It indicates EX forwarding but M stage result not yet ready for CSR instruction. It will stall IF/ID, ID/EX pipeline register and flush EX/M register. Let M instruction goto WB stage.  

### `ID_branch_stall`
Operand for branch/jump in ID stage needs forwarding and is not yet ready. There is two conditions:
1. ID rs1/2 matches EX rd and not x0
2. ID rs1/2 matches M rd and the result is not ready. 
    1. `M_Forward_Result_Ready`
    2. CSR instruction

It will stall IF/ID, flush ID/EX pipeline register. 

### `ID_redirect`
Branch/jump is taken, and IF/ID pipeline register not be stall. The reason for checking IF/ID is stall or not is to redirect PC when IF registers can goto next stage.

It will update PC to target address, clear IF buffer and flush IF/ID wrong instruction.

## Each pipeline registers
### IF/ID
- stall: if `Front_stall` is set up
- flush: if pc needs to redirect or if IF/ID is not stall but the instruction is incorrect

### ID/EX
- stall: if `DM_stall` or `FW_dep_stall` is set up
- flush: if `ID_branch_stall` is setup and `DM_stall` and `FW_dep_stall` are not set up. Since if the last two signals is set up, it means we need to keep the values for EX stage, which flush must not clear them.

### EX/M
- stall: if `DM_stall` is set up
- flush: if `FW_dep_stall` is set up


### M/WB
- stall: always zero
- flush: always zero
